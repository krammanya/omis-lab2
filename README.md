# Платформа учёта и анализа клиентского опыта (ЛР №2)

Учебный прототип по объектной модели из лабораторной работы №1. Python 3.10+, графический интерфейс Tkinter. Внешние библиотеки не требуются.

[Ссылка на источник](https://docs.google.com/document/d/1JXgMhNWrMSLc_gwflsKSDtxl6ipeM1hGh5j20Piiak0/edit?tab=t.0)

## Запуск

В папке проекта выполните:

```powershell
python main.py
```

Вход выполняется по тестовому аккаунту. На форме есть кнопки для заполнения данных:

| Роль | Email | Пароль |
|---|---|---|
| Клиент | client@example.com | demo123 |
| Менеджер | manager@example.com | demo123 |
| Бизнес-аналитик | analyst@example.com | demo123 |

Роль определяется аккаунтом. Пароли проверяются по PBKDF2-хешу; сессия получает случайный токен. При запуске создаются три продукта и десять отзывов с разными оценками. Все данные локальные, хранятся в памяти и сбрасываются после закрытия приложения.

## Структура проекта

- `main.py` — точка входа.
- `app/models.py` — классы пользователей, отзывов, ответов и других объектов.
- `app/services.py` — хранилище, репозитории, очередь и модули обработки.
- `app/algorithms.py` — правила анализа и формулы показателей.
- `app/accounts.py` — тестовые аккаунты и локальные сессии.
- `app/demo.py` — демонстрационные отзывы.
- `app/ui/theme.py`, `app/ui/layout.py` — оформление и каркас интерфейса.
- `app/ui/application.py` — главное окно и общее состояние интерфейса.
- `app/ui/widgets.py` — общие элементы интерфейса.
- `app/container.py` — создание объектов и передача зависимостей.
- `app/controllers.py` — выполнение сценариев отправки, анализа и ответа.
- `app/ui/screens/auth.py` — форма входа.
- `app/ui/screens/client.py` — кабинет клиента, отзыв и история.
- `app/ui/screens/manager.py` — список отзывов и ответ менеджера.
- `app/ui/screens/analyst.py` — панель аналитика и детализация.

## Возможности реализации

- Клиент выбирает продукт, оставляет оценку 1–5, комментарий и при желании отвечает на отдельный вопрос рекомендации 0–10. Видит историю и ответ менеджера.
- Отзыв сохраняется через `WebForm`, извлекается из очереди, анализируется; результат сохраняется репозиторием аналитики. Подписчик очереди оценивает признаки подозрительности.
- Менеджер фильтрует отзывы по тональности и статусу, открывает карточку двойным щелчком, читает категории, сущности и оценку доверия. Создаёт и редактирует черновик, отправляет один ответ. Повторный ответ отклоняется репозиторием.
- Аналитик выбирает период и продукт, видит число отзывов, среднюю оценку, NPS, число ответов и отзывов для проверки. Нажатие на столбец распределения оценок открывает соответствующие отзывы.
- Аналитика включает тренд средней оценки, корреляцию оценки покупки и рекомендации, сегменты клиентов. При недостатке данных значение не выдумывается.
- Отчёт сохраняется как объект в памяти и экспортируется в JSON через диалог выбора файла.
- Опрос создаёт внутренние приглашения клиентам выбранных продуктов; они видны в разделе уведомлений. Рассылки по электронной почте нет.

## Какие алгоритмы добавлены к диаграммам

Диаграммы задают обязанности модулей, но не конкретные вычислительные правила. По требованию сделать работающее приложение добавлены следующие локальные реализации:

- Тональность — словарь положительных и отрицательных основ слов, с учётом непосредственно предшествующего «не». Это эвристика; сложный контекст, сарказм и отрицания могут трактоваться неверно.
- Темы — доставка, качество, обслуживание и цена по словарям. Сущности — поиск известных названий и терминов. Это не обученная NLP-модель.
- Подозрительность — точные повторы нормализованного текста, очень короткий текст и частота публикаций клиента за минуту. Порог ручной проверки — риск от 0.6; оценка доверия равна 1 минус риск. Это признак для проверки, а не доказательство фейка.
- NPS рассчитывается только по отдельному ответу 0–10: процент рекомендаций 9–10 минус процент 0–6. Оценка покупки 1–5 в NPS не преобразуется. При отсутствии ответов показывается прочерк.
- Тренд сравнивает среднюю оценку первой и второй половины отзывов, упорядоченных по дате. Корреляция Пирсона связывает оценку и рекомендацию; она не показывает причинность. При недостатке вариативности значение отсутствует.
- Клиенты группируются по средней оценке: довольные от 4, нейтральные от 3 до 4, недовольные ниже 3.
- Черновики создаются по тональности и теме с помощью шаблонов. Подключения к генеративному ИИ нет; текст проверяет менеджер.

## Соответствие диаграммам и дополнения

Основные классы модели участвуют в сценариях. Зависимости собираются в `container.py`, обработку связывают контроллеры из `controllers.py`. Расширения очереди, метрик, панели и дашборда выполнены наследниками. Функции имеют тела до пяти строк исходного кода.

Добавлены `AccountService`, `SurveyService`, техническое хранилище и компоненты интерфейса. Эти детали необходимы для работающих сценариев входа и опроса, но не раскрыты на базовой диаграмме. В отзыв добавлено необязательное поле `recommendation` для корректного NPS; имена классов в коде английские. Словари, пороги и формулы приведены выше, чтобы их можно было объяснить на защите.

Буквальное соответствие всем диаграммам одновременно не заявляется: их противоречия перечислены в разделе замечаний. Приложение остаётся настольным Tkinter, а не веб-системой. Хранилище и сессии существуют только до закрытия приложения; обработка очереди последовательная, уведомления и опросы внутренние. Макеты адаптированы к новому оформлению. Поля расширений отзыва и ответа объединены в классах данных.

Отдельно проверено ограничение длины функций.
